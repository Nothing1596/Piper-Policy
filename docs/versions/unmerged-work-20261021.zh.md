## 本地 MoE token 上下文修复

本地工作区新增 `tools/token_context.py`、`tools/tests/test_token_context.py`、`docs/implementation/local-moe-context.zh.md`，并修改 `gpt.md`。初次核对时尚未进入 HEAD；随后由 `956f916` 提交并推送。固定旧快照 main@09256a5 不包含它们，新的 main 已包含模块、测试及说明。

功能是管理模型的有限工作上下文：先缓存完整公开图像和回执，再为输出、安全裕量和图片预留 token，只选入放得下的历史。旧公开回执压缩为可追溯的动作、测量、错误及后续尝试；结果变化不合并。当前 plan、未决问题、新画面及末次反馈优先保留，旧资料仍可通过 session_context 分页读回。

这不是学习权重、模型总结隐藏思考，也不是恢复机器人状态。历史图片重读不刷新 observation_id，不允许重放旧动作。当前源码 runner 尚未直接导入这个模块；试验接线在独立的冻结适配器中，不能声称日常 CLI 已自动拥有此策略。

使用前应明确模型上下文容量、原生计数接口、图片预算和输出预留，再由匹配的实验适配器调用。不能把 32k 模型的固定值推广为所有服务。部署时需要把实现、对应测试与适配器作为同一版本核验；本页不提供会加载模型的自动启动命令。

已有文档保存了 79 项相关检查及原生探针记录；这些是历史记录。2026-10-21 发布准备另运行上下文、session、plan 与反馈相关 41 项检查并通过，两者有重叠、不能相加，也不能据此判断模型任务完成率。细节见 [上下文说明](../implementation/local-moe-context.zh.md)。

严格独立 seeder 的文件/工具可见性没有验收，因此没有启动 seeder、生成研究 seed、回放研究序列或计算 GT 分数。所有研究指标保持 null。使用步骤停在接口及匿名包核验；将来需在独立可验收输入边界下生成 seed，再另行进行条件回归。不能让已接触 GT 的会话直接填 seed，也不能把完整宿主目录交给 seeder。
