# Harness session 上下文与缓存（2026-10-13）

## 三个问题

1. **原实现有没有独立上下文压缩？** 没有完整机制。runner 只裁剪自己消息里的历史图片，agy 适配器只增量送消息；agy 自己的会话仍积累图片工具结果、文本和工具定义。两套历史并不相同。新实现由 harness 保存公开资料，再确定性提取当前工作上下文，不使用额外模型写摘要。
2. **agy 自带压缩有没有影响？** 有。v3 双相机在第16次决策、单相机在第19次决策发生压缩；首轮工具定义没有可靠保留。现在一个任务对应一个持久 harness session，每次外层决策启动新的 agy conversation。单次长调用仍可能在 agy 内发生压缩；公开缓存的恢复路径仍可读，因此不声称关闭或修改了 agy 自身机制。
3. **推荐机制是什么？** 原始公开证据落盘、不覆盖；热上下文只放原任务/skill约定、当前计划与状态、最近实际反馈、最新画面和最近两次模型候选；更早内容按需取回。完整工具定义每轮交付，并持久保存。历史图仍是历史图，不因重新查看而取得动作授权。

## 已实现范围

当前接入 `tools/agy_online_decider.py` 和 `run_gemini_camera_pair.py` 使用的实验 CLI 路径。`tools/session_context.py` 不依赖模型供应商或机器人，用普通JSON/图片保存公开材料。未添加普通交互 CLI 的 `/context` 命令，也没有自动安装或修改用户 agy 配置、真机部署。

- harness session ID 整个任务保持不变，provider conversation ID 每次决策不同，分别记录。
- agy 退出只释放模型进程，不断开/重启机器人执行器，不重发动作。
- 每个conversation的累计usage从零计量，任务总量按回执相加；缺失usage仍明确失败并保留原始回执，不当作零费用。
- `public/context/turns/turn-003.json` 保存第3号轮（从0编号）输入公开信息及图片清单；相邻 `-decision.json` 保存模型候选，`-results.json` 保存实际工具结果。二者不能混同，最后一个工具的反馈也保存。
- `public/context/index.json` 是完整索引；`current.json` 是当前工作上下文；`tools.json` 是准确工具参数定义。上下文、工具文件的哈希进入调用回执。
- 原始公开图片保留精确路径、哈希及来源标签，已裁剪出热上下文的图仍可读。hook仅放行明确登记的公开文件；缓存文件读取与图像查看分别计数。
- 只读缓存可由新的模型进程读回，不等于支持自动从断线点续动。运行器没有新增自动恢复/重放接口。

## 模型怎样主动找第3轮图片

可以直接 `view_file` 打开提示中的精确索引路径，再打开对应轮次JSON及图片。也可通过实验中暴露的只读工具：

```json
{"name":"session_context","arguments":{"operation":"list","start":0,"limit":10}}
```

```json
{"name":"session_context","arguments":{"operation":"read","turn":3}}
```

返回第3轮记录中的图片路径、来源、公开消息、模型候选及实际工具结果。读取原图使用返回的精确 `AbsolutePath`，不拼接/猜测文件名。

需要放大查看局部，可裁剪原图：

```json
{"name":"session_context","arguments":{"operation":"crop","image_id":"frame-008.jpg","roi":[180,160,240,225]}}
```

`frame-008.jpg` 仅为示例，必须换成索引中存在的 image_id。ROI 是原始像素坐标 `[x0,y0,x1,y1]`。返回实际裁剪像素和到原图坐标的映射，并标记 `HISTORICAL`。这不是新拍摄，也不自动产生深度、标定或空间测量；当前实现没有为旧图新增任意代码处理工具。

历史读取/裁剪可和独立只读工具合批，机器人状态变更仍遵循已有协调和实时反馈检查。用历史 observation_id 提交动作会被拒绝，不会隐式切换 gate 最新状态。

## 明确的 CLI 错误修复

- 首轮才交付参数表导致压缩后猜字段：改为每轮交付与公开缓存恢复。
- 旧图仍在磁盘却不在当前白名单：累计登记全部本session公开证据，继续校验哈希和路径，不放开评分文件。
- agy 压缩建议读 transcript 与原 hook 冲突：拒绝中返回公开 current/tools/index 精确恢复路径，不开放私有 transcript。
- 参数校验只报第一个缺失字段：一次返回所有字段错误、原始正确schema及 `executed:false`。不把 xyz 自动改成 xyz_m，不伪造 request_id，也不静默忽略多余字段。
- 加入JSON缓存读取后可能虚增“看图次数”：图像计数只统计成功的 jpg/png 读取。
- camera_observe 文案写只接受 `{}`、默认固定相机，与实际serial/实验条件不符：同步实际工具说明。

## 验证边界与取舍

每次决策新CLI会话防止长任务记忆依赖供应商摘要，但会增加进程启动、工具定义交付和部分当前图片重读的开销；这属于新的上下文策略，不能把后续结果与v3直接当作单相机数量消融。没有宣称更省token或提高任务成功率。

测试覆盖历史图从热上下文淘汰后仍可读、文本/图像篡改和越权读取、裁剪溯源、末次结果保存、新CLI会话usage累计、历史图不能触发旧观察动作、全部字段错误一次反馈及既有动作链回归。

本轮不改几何ROI单对象判定、放置路径或评分器，不启动新的单双相机任务。原实验冻结代码和结果保留。
