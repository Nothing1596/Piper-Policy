# CLI 契约与候选复核 pilot（2026-10-13）

## 问题与实验边界

上一轮四个独立选区回合均读取一次图片、四个缓存 JSON，并尝试一次不需要的内置指南读取。拟检验：去掉不相关机器人说明并明确缓存按需读取，能否减少额外行为；另外单独检验模型看到旧候选轮廓后能否修订选区。

产物：`/Users/nothing/DEV/piper-contract-pilot-20261013/`。A/B 使用上一轮冻结的 decider/guard/cache 源码，保持相同图、模型别名、输出格式和文件权限。neutral 是整段说明包的替换，不是单个句子的消融。每组只有一次，固定顺序，不能据此声称统计或普遍因果。feedback 是单独的可行性探针，不能混进 A/B。

所有输入都是录制图，没有硬件或模拟器动作。原图、提示、输出、模型调用回执分别保留。代理模型用量包含 CLI 内部自动修正；不把外层一次请求写成只调用了一次模型。

## 已确认的接口缺陷及最小修复

neutral 的第一段公开输出把 `view_file` 放进了应当返回给 harness 的 `tool_calls` 数组，尚未实际看图；CLI 随后自动继续，在后续步骤真正调用原生读图工具。原先 envelope 中工具名只约束为字符串，未向 CLI 的结构化输出层传递当前有效名称。

修复只涉及 `tools/agy_online_decider.py`：

- 每轮从现有工具目录生成返回工具名的 enum，写入本轮启动所用 response schema。
- 明确原生 `view_file` 必须直接用于看证据，不能放进返回动作数组；返回数组只能选择提供给 harness 的工具。
- 原有 runner 参数校验、请求幂等、动作权限和实际图片查看回执保持不变。

这是契约准确性修复，不宣称它解决了额外文件读取或 token 开销。单独 strict 回合验证新 schema 能被真实 agy 接受；没有修改运行中的冻结 A/B。strict 与部分 A/B 在时间上重叠，不能用墙钟差异声称严格速度对比。

本轮相关回归 83 passed，覆盖原生读图名称不能混入返回数组、每轮允许名称更新、历史缓存、图片查看核验、工具透传和动作反馈边界。neutral 未提升的情况下，不将其替换为默认入口。

## 对标与后续假设

核对本地 GPT-Policy 源码快照 `3a74ed4b45d25ff9af4939c9209292e725712f50`：`tools/catalog.py:138` 将启用的工具名写入输出 schema；`harness/providers/codex.py` 保持 session 到图像窗口达到阈值或恢复条件触发，再刷新并重放历史。它不是无条件每个决策都刷新。

当前 Piper 的每决策新 conversation 策略虽然隔离了历史累积，却可能重复支付 CLI 初始化/环境理解成本。短说明 A/B 不足以区分该原因与模型推理配置；下一项合适的小测是固定任务和输入，比较两轮内复用 conversation 与每轮刷新，保留同一个 harness 缓存及相同工具、图片回执。先测，不立即改变默认生命周期或重新引入不可控历史增长。

候选反馈 probe 仍需与物理成功分开：模型修订框不证明深度中心正确，图片颜色统计不等于完整物体分割。旧深度的远端复算和真实短放置仍待网络恢复及后续验收。
