# 公开行为复核 v1（2026-10-16）

本轮只增加任务级的确定性诊断，帮助模型注意重复查询、未改变条件的拒绝、计划序列缩减和无依据的完成声明。它读取模型已经获得的公开工具结果，不读取私有评分状态，不分析隐藏思考，也不替模型决定抓什么、怎样移动或任务是否成功。

## 接入位置

- 原生交互、JSONL 和标准 MCP 共用 `InteractiveConsoleController.invoke_tool`，在原始调用结束后附加 `harness_review`。不新增机器人调用，不改变动作参数、状态、request_id 或已有审批。
- 原生模型每次 API 请求前刷新当前任务及监测状态。同一任务跨多轮用户输入保留监测状态；新建/切换任务以及切换配置目录会隔离状态。读取归档任务不自动切换当前任务。
- 在线实验 runner 可显式使用 `--behavior-monitor`；已有 `video_plan_workflow` 工作流也启用该诊断。report 中记录 `behavior_monitor: public-behavior-v1`，逐轮事件保存复核结果。诊断不增加模型请求或机器人查询。
- 原生前端的诊断快照写入当前 profile 的 `harness/<session>.jsonl`，包含时间、任务、调用序号及问题引用。它是审计快照，不是执行器日志、完整上下文缓存或进程重启后的物理恢复检查点。

## 四类提醒

| 规则 | 公开证据 | 返回含义 |
| --- | --- | --- |
| 重复查询/查询循环 | 同一观察、参数及相同结果，在最近 8 次记录中出现第 3 次；或相同证据上的 A/B/A/B 查询 | 复用已有结果，或说明新查询要排除什么不同假设 |
| 忽略拒绝反馈 | 更换 request_id，但目标、观察和拒绝结果重复 | 说明哪个前提已改变；仅换编号不代表新证据 |
| 计划序列缩减 | 原有稳定步骤 ID 消失（自由动作措辞修改不等于步骤缺失） | 保留此前序列用于复核，解释修订依据，避免只留下终态 |
| 无依据完成 | completed 步骤缺少真实请求/观察引用，或只有失败、受阻、拒绝、未知结果 | 补充成功恢复和实际结果证据；不自动修改模型写下的状态 |

新画面/不同选区/不同结果不会被上述查询规则当作同一测量。已成功动作会开启新的证据阶段。任务状态轮询与同一请求的结果查询不计为第二次执行；查询可将未知回执对账为已知结果，诊断不会重发请求。

诊断比较窗口为最近 64 条行为，保留最近 512 个回执和 16 条问题，返回最近 8 条未解决问题；`occurrences` 是保留期间的诊断次数，不是整个实验的累计错误数。实验累计调用和用量仍取原有账本。重启前端后未加载的历史回执只标为本会话无法核验，不断言过去执行失败，也不要求重做动作来产生新回执。

这些规则刻意保守。例如，更换很多相邻像素的低效搜索未必会触发；出现新帧也不证明模型获得了有用信息。一次 succeeded 原语只满足回执一致性，不证明物体已经搬运、松开、撤离或保持稳定。独立终态评分与已有执行约束继续负责各自的判断。

## 提醒如何变化

状态为 `working → needs_review → verifying`。只改 `current_stage`、重复读回同一版本，不能消除问题。修改解释后可进入待验证；重复问题只有出现不同的成功查询或成功动作后才按公开行为改变处理，不把它记作语义任务进展。序列缩减仍保留原步骤供核对；恢复原步骤可解除该提醒，带依据的修订可以继续执行。修订后再次重复同一问题，会返回 `needs_independent_review` 建议。

此版本没有自动调用监督模型，也没有自动压缩、重开模型会话、复位场景或清空任务。独立复核只是提示。plan 仍是软约束，任一上述状态都不阻止动作或停止；原有未知执行结果、反馈时效、限位与审批规则不变。

诊断或审计写入失败时，返回诊断不可用的信息并完整保留原始动作结果。不能把已知执行结果转成会诱导重试的传输错误。

## 两处同步修复

1. 视频计划的 completed 引用现在核验回执内容，失败/受阻请求不能仅凭“编号存在”支持完成；失败后又成功的恢复可以同时保留两条回执。该检查仍不替代语义及物理完成验证。
2. runner 不再把任意成功的 `task_plan.update` 当作所有执行检查点已复核。放爪/受阻检查点需出现在具体步骤的 `execution_refs` 中；只更改阶段名不会清掉遗漏提醒。它仍是提示，不要求为了继续运动而满足 plan。

## 验证边界

本地测试覆盖规则边界、任务/模式隔离、跨用户轮次上下文刷新、回执对账、日志故障、停止可用性，以及实际 JSONL/MCP 仿真进程的结果传递与退出清理。使用模拟结果验证协议行为不等于真实物理任务成功；本轮没有进行付费模型任务对照、远端部署或真机验收。

本机 macOS 的完整相关回归结果为 **839 passed、8 skipped**。首次发现一个现有 MuJoCo 测试的时序假设：它在动作发布 succeeded、工作线程尚未完成日志收尾时，就断言 stop 只能走 idle 路径。最小修复仅让测试等待该线程结束；未改停止实现。随后对真实相机帧身份和历史回执不可用补充针对性测试，最终 **40 passed（4.27 秒）**，和完整回归有重叠，不能相加。

通过终端 Claude CLI 做只读复核。第一轮因工具读取达到回合上限没有产出结论；改为直接交付限定代码后完成复核。其指出的重复失败 request_id 被去重漏过问题已修复并回归；有界问题缓存的次数只覆盖保留窗口，按设计保留并在此注明，未扩展成另一套全量统计系统。

旧冻结实验目录和已完成结果保持原样。未来比较时须冻结新代码与 skill，并分别统计新增提醒、提醒后的实际行为改变、调用/token 和独立任务成功率，不能凭测试通过就声称模型性能提高。

## complex 对照发现后的修订（2026-10-16）

保留 `piper-ds-behavior-complex-20261016` 的原始记录。该轮新组完成、旧组因模型 JSON 少一个结束括号暂停；不能把这一差异直接归因于复核引导。当前作出四项局部修复：

- plan 候选的预检查容忍无效 JSON/null/数组，让统一参数校验返回 `executed:false` 的工具错误。既不补括号，也不执行未校验参数；后续由模型决策纠正。
- `plan_shrink` 只依据稳定步骤 ID 消失提示。自由动作措辞改变不再触发；恢复同一 ID 可以解除提醒，不要求逐字恢复。该规则不能判定同一 ID 下语义偷换或重排，需独立评分与模型核对，避免用字符串猜语义。
- runner 在模型工具层监测重复行为。原生前端对子调用的诊断保留在 `native_harness_review` 审计事件，不混入模型反馈。原生调用总数保留，另按 `model_tool` 和 `adapter_internal` 来源计数；同帧、同标定、同桌面选区的成功平面拟合可缓存，`internal_plane_cache_hits` 与模型读缓存分开统计。新取帧/重连清除该平面缓存。
- 动作后读回 plan 实际版本，随已知动作结果返回 `plan_writeback`；不自动写 completed、不改写模型 expected_version。同批次过时的更新返回当前 plan，模型应在下一次决策基于真实反馈写回。plan 同步失败不能抹去已知动作结果，下一次决策仍要求同步成功。

对照时使用相同修复后的代码、视频引导、软 plan 和执行条件，仅通过 `--behavior-monitor` / `--no-behavior-monitor` 控制复核反馈。它估计复核反馈在本地模型上的影响，不复刻旧崩溃缺陷，不等同全部新旧 harness 的因果比较。
