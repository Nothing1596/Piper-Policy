# 八组真实接触仿真小实验（2026-10-11）

研究目标：DeepSeek 使用已有 CLI/MCP 和共同计算后端，在实际 MuJoCo 接触物理中执行人类 complex 示范，比较显式 plan、流程 skill、请求推理强度的作用。不是生成 code 与 LongVIL 答案匹配。本轮仅修改在线实验适配与作业编排；沿用既有机器人、控制器、几何计算、场景和传感器修复，不继续扩展底层。

## 变量与共同合同

| 条件 | Plan | Skill | Effort |
| --- | --- | --- | --- |
| P0S0-low | off | off | low |
| P0S0-high | off | off | high |
| P0S1-low | off | on | low |
| P0S1-high | off | on | high |
| P1S0-low | on | off | low |
| P1S0-high | on | off | high |
| P1S1-low | on | on | low |
| P1S1-high | on | on | high |

所有条件均开启模型 thinking，允许内部规划。Plan-off 只关闭模型可见的外部计划存储与协议，后台仍建立空几何容器供现有 scene_query 使用。Plan-on 在首个动作前 get→下一决策 update，在公开闭合/张开周期后读写进度，最终动作后 get→下一决策 finish。空抓也需要记录进度，不将检查点标记为成功。task_plan.guide 不向执行模型提供，防止 skill-off 间接取得流程指导。

Skill 只增加同一份 observe-and-plan SKILL.md 的非持久观察/证据流程指导；不增加计算或运动工具。根据当前固定相机适配器，去掉不支持的问题绑定捕获语法，保留同一实际指导文本。两种 plan、两种 effort 的 skill-on 文本和哈希一致，skill-off 文本为空。共同合同只说明目标、工具接口、单位、参数、新鲜度、异常与终止语义，不混入强制计划或额外观察流程。

除有意增加的 task_plan 外，各组的已有 CLI 原语、scene_query、IK预览、只读抓取/放置计算及描述/参数 schema 一致。运动参数保持 speed_percent=10、timeout_s=60、effort_protocol=0.5（适用于对应工具），不改变底层限制或控制器。所有组得到相同的12张真实初始示范帧及可补看的冻结证据；动作后的当前图来自本组实际执行，轨迹不同不会要求后续图片完全一致。图片保留初始概览、最近一组补看和最近两组当前图，均有来源、身份和时间。

正式每轮统一：deepseek-flash（现有 DS 配置）、thinking enabled、累计65,536 completion tokens、80次 API、120次模型工具、1,800秒新调用启动预算；单次 API 超时300秒。上限不是实际消耗量，分别记录 reasoning/completion tokens、计划读写、其他工具、运动请求、费用及时间。请求参数与返回别名可冻结记录，不声称冻结供应商权重或精确算力。

模拟器保持已有实时推进规则。high/plan 增加的调用与等待会影响物理持物时间，属于本轮端到端系统效果；不能解释成排除延迟后的纯推理质量。计划调用也占同一预算，不给 plan-on 补额外预算。

## 固定样本、预试与冻结

正式任务固定为两个已审核且参考程序已通过真实物理预检的 complex 视频：level1_4_vegetablesorting_4、level2_8_blockmanipulation_8。选择依据是已有审核/物理可行性，不依据八组的模型成绩。两段各八组一次，16轮。只有两个独立语义任务，不把16轮称为16个独立任务；不扩大到三难度全覆盖、新任务泛化或真机结论。原九场景预检与离线作业保持不变。

先用已查看、且不计入正式样本的 level1_4_blockmanipulation_3 做八轮接口预试。共同开发目标是读取证据、仅将空夹爪打开至0.07米、检查实际结果和新帧并结束；禁止其他运动，不复现其抓取视频。检查全部条件能完成接口；P1还需完成必要计划读写。验收以接口/协议/资源为准，不按哪组抓取成功率更高选择提示。

冻结前已完成 Mac 相关回归122 passed；Linux 标准 MCP 初始化、模拟连接、当前 RGB-D 与退出探测通过，未调用模型 API、费用为0。场景文件哈希与原物理预检一致，八组除计划工具外的工具 schema 哈希一致。dsh 通过终端做了独立静态审查；采用提示结构校验、真实版本绑定、分类记录建议，不采纳与逐轮独立实例实现不符的状态复用推测，也不合成异常 tool-call ID或给某组额外预算。

源码、共享 skill、各条件实际提示、任务名单、原注释、帧与评价、场景身份、模型参数、价格快照说明及随机排程均保存哈希；随机种子20261011，在任务区组内打乱八条件顺序。每轮新模型对话、task_id、profile和模拟器，退出检查所属进程身份。八轮开发门槛通过后写 formal-freeze.json，随后自动执行已授权的16轮正式作业；不在开发期间改求解器或按成绩改提示。

## 评分、失败与报告

主要物理指标是实测有序转移：正确操作对象、真实双指抓持、至少3cm抬升、受控释放和规定物理关系。模型自称完成、接受的命令或文字程序不代替目标达成。plan协议完成与模型结束声明单列。SDK已执行后超时/未知结果终止当前会话、保存任务执行失败；确认清理后，下一个独立条件从新初态运行，绝不重放旧动作。预算截断单列并保留，不择优丢弃。

API/传输/响应/用量或资源清理异常属于基础设施暂停，停止后续请求，不自动重试。失败的已评分编号不重跑。显式续跑跳过已有评分；先前未完成会话要另加 --retry-incomplete 才能从新初态建立新 attempt，保留原日志和费用。这不是未知运动的重发。未知用量预留3元单列，不称为实际消费。

只对八组齐全的任务块计算描述性差值：对每个任务，plan-on−off、skill-on−off、high−low均先平均另两变量的四个配对，再平均任务。改善、持平、退化都保留；两个任务不做显著性结论。逐轮日志可进一步检查交互、用量与时间。本轮没有生成新的官方 EMA/FSA 成绩来替代物理指标。
