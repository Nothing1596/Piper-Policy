# Gemini 新会话单/双相机仿真对照（2026-10-13）

本轮只修实验入口，不扩展机器人后端。既有成功案例保留，但由于此前外层会话曾读取私有 GT、IPC 丢弃示范图片且用量由适配器填写，不能作为本轮干净对照。

## 固定条件

- 同一已审核 complex 示例：`level1_4_blockmanipulation_3`，同一已有腕部相机版 MuJoCo 场景，每轮从新环境开始。
- 两条件：固定相机；固定＋腕部相机。单相机条件在调用层禁止请求腕部图。双相机是顺序采集，非同步多视图。
- `agy --model gemini-3.8-flash-high`，plan/skill 都开启，每条件全新 CLI 会话；不恢复旧对话，不推断供应商实际权重或 Argon 身份。
- 同一示范帧、CV 评价、工具、65,536 累计 completion、80 次决策、120 次机器人工具、1,800 秒新调用启动上限。CLI 真实生成超预算时禁止派发该响应，不宣称 CLI 具有服务端硬 token 上限。
- 固定种子 20261013 排列两条件。两次运行只用于流程与个案对照，不宣称统计显著性。

## 证据与隔离

决策进程工作目录只含公开图片和工具拦截配置。工具 hook 仅允许查看本轮 SHA256 白名单图片以及 agy 内部结构化输出 `finish`；终端、源码、网络、GT、其他会话和委托工具全部拒绝。这里是 CLI 工具边界，不是操作系统沙箱。

示范/实时/候选叠图均保留实际像素、来源标签、帧身份和时间。首次示范图片及每批新实时图片须有成功 `view_file` 回执，才接受机器人请求。每个模型响应最多一项工具请求；执行后返回真实结果与新帧，下一次真实 CLI 决策才能继续。编排程序传递反馈，不生成操作脚本或预设动作队列。

私有 GT 仅由编排器在决策与 MCP 会话关闭后读取评分，不送入模型。模型只看到公共物体名单、示范和实时反馈；它的成功声明与独立物理评分分开。

## 统计与异常

分别记录：请求/响应、PreInvocation 模型生成次数、机器人工具尝试与结果、辅助 MCP 调用、实际查看图片次数及唯一图片数。CLI 累计 usage 按相邻回执取差，thinking 已包含在 output 中，不重复相加。无费用回执写 null；usage 不完整写未知，不能写 0。

所有原始 CLI 流、图片清单、hook 允许/拒绝事件及回执保存。缺图、未知用量、传输失败、未知执行结果或资源未释放均暂停，不自动重跑。接口预检单独编号，不计任务成绩；已评分失败保留。

入口：`tools/run_gemini_camera_pair.py --config CONFIG.json --output NEW_DIRECTORY`。配置包含独立 WSL 模拟器目录；代码、图片和私有评分资料冻结在决策目录外。旧服务、真机和历史成绩不改动。
