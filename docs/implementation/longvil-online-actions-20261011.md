# LongVIL 示范到在线 Piper 动作链（2026-10-11）

目标是让模型通过正常 CLI/MCP 发出实际运动参数，并在下一次决策中收到真实工具结果和新的模拟 RGB-D。旧 `run_longvil_physics.py` 先生成完整程序，再交给固定播放器执行，执行画面不返回模型；该路径有接触物理，但不属于在线模型控制。

本轮新增 `tools/run_longvil_online.py`，沿用 Featurize 原生 Linux 的 MuJoCo 3.14.0、正常前端及执行器生命周期。先用参考程序已通过接触物理检查的 `level1_4_blockmanipulation_3` 做开发验证。场景、机器人参数、限位和资产不改动；此前九场景对照作业仍停在物理预检失败，不把本轮记录混入它的成绩。

## 实际交互与计算

模型收到物体名单、带真实时间标签的录制示范，以及当前模拟 RGB-D。模型自行解释示范、选择对象和参考关系，然后调用 `task_plan`、`scene_query`、`move_to`、`move_linear`、关节及夹爪等工具。没有 `submit_program`，没有将语义程序转为动作的播放器，也没有向模型提供命名对象位姿 oracle。私有动作答案只在 API/MCP 会话关闭后进入评分。

一次响应最多一条运动请求。模型填写的实际运动参数原样交给正常 MCP；薄 runner 只移除用于核验新鲜度的 `observation_id`。保存意图、SDK 结果，再取得身份一致、时间晚于动作结果的新图；模型在新的调用中决定下一动作。未知动作结果、传输失败、缺少 usage 或异常模型响应暂停，不重发动作或自动重购调用。

两个只读计算适配器复用现有确定性后端：`preview_move_to` 用实测关节做 IK/限位预览；`grasp_target` 接收模型选择的对象 ROI 和桌面 ROI，用标定 RGB-D 拟合支撑平面、过滤桌面背景，并提供接近/抓取/抬升的参数与有限 IK 解。它们不移动机器人，也不证明碰撞安全。抓取估计假设对象直立并放在桌面上，点云仅覆盖可见表面；无 CAD 或隐形物体几何输入。

软件直线控制原先会在伺服尚未追上参考值时继续推进参考，可能触发已有 0.3° 跟踪检查。现改为在误差超过 0.12° 时保持当前参考、等待实测关节追上，再推进有界参考。跟踪拒绝阈值、超时、硬限位及伺服参数均未放宽。原生 5 mm 直线测试已通过；不推断任意长路径或接触路径都通过。

## 进度检查点试跑

job-03 的大量推理发生在动作前坐标换算和放置后重复核对。它只写过一次 plan；状态仍停在最初抓取阶段。本轮局部修正：

- 每张当前图提供实际传感器标定和相机射线轴方向。该坐标信息来自正常模拟 RGB-D 的外参，允许用于定位；不来自任务答案。
- 每次模型调用附最新的模型自写 plan、上一条实际 SDK 结果，以及最多三份带原观察身份的历史测量。旧测量不被重新认证为当前目标。
- 第一条运动前写 plan；公开 SDK 观察到夹爪闭合再张开后要求更新阶段和解释，包括空抓。该检查点不代表搬运成功。结束前在最后动作之后读回最新 plan。
- 仅同一采集身份、标定、关节状态及完全相同输入的只读计算可命中缓存；跨帧不复用。动作从不缓存或重放。

job-04 从新初态独立运行，仍使用 deepseek-flash/high、累计 65,536 completion tokens，40 个模型回合、80 次模型工具尝试。源码快照与远端 137 个文件已核对哈希。没有恢复或伪造 job-03 的结束状态。首次抬升完成时，job-03 用 44,388 completion tokens，job-04 用 20,717；两次开发配置包含多项修正且没有重复，不能据此单独证明 plan 的因果收益。

job-04 最终在约 384.8 秒、26,575 completion tokens、估算实验 API 费用 0.3135 元时停止。私有连续录像记录了第二根手指与绿色长方体的接触（末次记录三个接触点约 1.26/1.89/0.39 N），圆柱倾倒。源码检查显示模型将绿色长方体的最小夹持宽度用于图像左侧方向的间距，这是不同轴的尺寸，不能混用。未知动作没有重发；退出核验本轮 PID 不存活、runtime 已删除、录像无错误。

## 方向尺寸与放置计算

新增实验只读 `placement_target`：模型提供来自本会话的 source_measurement_id、当前参考物和桌面 ROI，以及示范中的关系。后端复用 plane/region 计算，沿实际标定图像方向投影可见包络，并用源物体记录的 TCP 高度估计桌面放置或顶部支撑的位置。源物体的包络根据夹爪当前 yaw 变化旋转，保留其观测中心到抓取 TCP 的偏心；沿方向间距还考虑固定 `piper_x.xml` 的指爪臂包络。倾斜桌面高度在最终落点计算，非法关系、污染 ROI、未知测量身份和标定变化拒绝。

该适配器只给出端点参数及有限 IK 解，不新增动作、不自动执行或规划整条路径。可见点云包络不等于完整形状；源物体相对夹爪无滑移、保持直立是明确假设。没有验证全部机器人连杆/场景碰撞，默认间隔也不能被称为碰撞证明。

job-05 是修正后的独立新会话，继续使用相同预算和原始场景，不恢复 job-04，也不重发其超时动作。冻结源码与远端 137 个文件一致。原试跑结果、程序和费用均保留，后续结果单独保存。

job-05 已退出：606.8 秒，56,426 completion tokens。26 次 API 尝试中25次返回有效用量，第26次是 `ConnectError`，没有模型响应。账本已核验的估算费用为0.5087元，另保守预留3元未知用量；3.5087元不是实际消费。之后仅做无认证 HTTPS GET，返回401，说明当时连接可用，不证明失败请求的具体 DNS/TLS 原因或计费情况；没有新付费请求或自动重试。

公开 SDK 最后一次下降成功，但夹爪宽度从约0.0536米降到0.025米，双指接触消失；这次反馈交付之后 API 中断，不能说模型已忽略或修正它。退出后的私有记录显示圆柱已经在桌面，竖直包络约0.0698米，与初始约0.10米不同。当前仍缺少抓持后物体姿态/滑移的计算证据，原抓取尺寸与双指力不能保证物体一直直立。独立评分已补充受控释放要求，途中掉落不能因为最终关系碰巧成立而记作成功。这项评分修正未重写旧作业。

## 停机后的局部修复与验证

API 账本的保守暂停原先会掩盖连接异常文本。现在先保存不含密钥和推理正文的单次请求回执，再记账；HTTP 状态、连接异常类型、响应摘要与是否有 usage 都可单独核验。API 尝试和有效响应分开计数，基础设施异常依旧暂停，不自动重试。该修复只做软件测试，没有重新发付费请求。

确认了模拟传感器会把红色 TCP / 绿色法兰调试 site 渲染为 RGB 和深度目标，容易增加对象歧义。独立原生测试中，TCP 投影位置默认深度约0.5300米；排除 site 后是实际桌面约1.1000米。修复仅在 sensor observe 中关闭调试 site，全部物理和视觉 geom 保留，GUI 调试定义与物理状态不变；深度渲染异常后恢复渲染模式。Linux 新源码只读复核通过，tx_frames=0。没有将修正后的图像倒填进 job-05 或声称已经重新验收任务。

最新 Mac 相关回归为 **107 passed**，覆盖在线反馈（包括停止后的新帧）、plan 检查点、已知/未知结果、实际引用、缓存隔离、方向包络、偏心与指爪尺寸、受控释放、API 回执和传感器模式恢复；有一条既有 Starlette 弃用提示。另有 Linux 原生传感器渲染核验。它们不是完整视频任务、Windows、CI 或真实硬件验收。

直接通过终端调用 dsh headless 完成静态审查，没有创建 sub-agent。审查建议中的历史证据标记、空抓检查点和缓存身份约束已处理；不采纳“隐藏标定位置以防模型定位”或“退出时自动松爪”：前者与本轮视觉控制目标冲突，后者会在未知结果后追加动作。审查不替代运行验收。
