# LongVIL v2：推理长度还是 plan 工作流？

这份分析使用完整的324轮主实验。54轮快速视觉初始化消融已显式续跑，其结果不进入本次主比较。三组均请求deepseek-flash/high/65536，API/工具/时间上限相同；A也可在内部规划，不能称作“模型不规划”。没有额外付费实验。

## 当前判断

数据不支持“C只是因为生成了更多累计思考token而获益”这一简单解释：C比A少思考约12.3%，成功数却多7个；C比B仅多5.4%的思考token，而不是把推理长度成倍提高。不过，C增加了分阶段API调用、结构化记录和重复视觉上下文输入。当前实验估计的是这个工作流组合的效果，不能把收益独立归因于磁盘持久化，也不能排除额外多轮复核的作用。

## 用量核验

## 配对行为和效果集中位置

C/B在108个对应任务×视频×重复上比较：C有5次改善、1次退化，净多4次成功。按27个语义任务合并，每任务保留两视频×两重复，净改善集中在4个level3任务；其余23个任务净差为0。level2一个任务的一次改善和一次退化相互抵消。

| 难度 | A成功 | B成功 | C成功 |
|---|---:|---:|---:|
| level1 | 35/36 | 36/36 | 36/36 |
| level2 | 33/36 | 35/36 | 35/36 |
| level3 | 20/36 | 20/36 | 24/36 |

在5个C改善的配对回合中，3个C使用的思考token反而更少；但5个C均有更多API调用和更多图片输入次数。它反驳了“每次改善都靠写更长思考文本”的必要条件，却无法排除多轮交互或重复阅读的作用。这个分组按运行后的用量定义，是事后描述，不是控制变量实验。

## 不确定性

B−A点估计+2.78个百分点，预定5000次任务级bootstrap的97.5%区间为[−1.85,+7.41]。C−B点估计+3.70个百分点，预定有限抽样区间为[+0.93,+7.41]，但同一重采样分布的精确敏感性计算为[0,+8.33]。只有4个任务有净改善，有限抽样的下界临界，不宣称稳健显著性。敏感性检查不替换或删除预定结果。

## 为什么不直接回归“成功率～plan＋实际token”

实际用量发生在分组之后：plan可能改变关注的问题、补看次数、判断方式、API轮数和最终用量；困难任务与本次模型的不确定性也会同时影响用量和结果。把实际token作为普通控制变量，可能控制掉工作流自身的作用途径或引入选择偏差。相同实际token的回合也不一定面对相同的不确定性。因此这里不把事后token匹配或回归系数解释成“排除了计算量之后的plan因果效应”。

对应方法依据：[Cinelli、Forney、Pearl的Good and Bad Controls原文](https://ftp.cs.ucla.edu/pub/stat_ser/r493-reprint.pdf)。对中介变量的条件化会改变要估计的效应，且可能打开碰撞路径。

[s1原文](https://arxiv.org/html/2501.19393v2)把实际预算控制与自然生成长度分组区分开：仅在提示中要求某个长度并不可靠；该论文的预算强制技术涉及生成时控制。其数学任务结果不能直接移植为LongVIL的因果证据。我们的API实验没有干预单独的累计思考长度。

## 最小下一轮方案（仅建议，未运行）

先增加一个“B＋固定通用复核”对照：没有task_plan持久化或特定计划字段，但给它与C一致的预定API阶段、图片输入日程和工具观察预算。复核只要求检查遗漏、关系、顺序与程序合法性。然后在B复核/C plan两种工作流下交叉分配两档相同的累计生成预算。

- 随机分配预算和工作流，按相同任务/视频区组配对，保留失败；不能按已观察成绩挑样本。
- 预算约束由runner按usage扣减累计completion tokens，并把它明确命名为“思考＋公开输出的累计生成预算”。API不能保证独立精确控制思考token，不假装做到了。
- 图片日程、可调用观察次数和复核阶段预先固定；如想研究主动补看的收益，再作为独立因素变化。
- 与C同样分阶段的通用复核若也获得相近收益，说明额外复核可能足够；C在这些预算档仍稳定领先，才加强结构化plan诱导的证据。
- 若要单独研究持久化，保持同样的plan提示和内容，只变化存储/恢复。单回合文字历史已保留时，当前数据不验证跨会话恢复或长上下文记忆的优势。

当前可报告：在相同请求配置和上限下，plan工作流具有小幅正向点估计，增量主要集中在困难任务，未显示必须生成更长思考文本。不能报告：已独立证明持久化存储有用，或者已排除多轮视觉复核的计算收益。全部结论只针对离线动作语义与符号评测，不扩展为真实3D定位或真机成功率。
