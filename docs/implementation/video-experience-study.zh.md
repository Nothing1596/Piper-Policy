# 视频经验与 Argon 完整任务对照

2026-10-14。实现位于 `tools/video_experience.py` 和
`tools/run_argon_video_study.py`，仅作用于实验入口；日常 CLI、真机审批和
控制器均不改变。

## 固定安排

- 9 个既有已审核 LongVIL complex 任务，原始场景初态，完整执行；不使用
  “圆柱已经搬好”的局部抓取布置。
- `gemini-4-argon-high`，固定 overview 相机，plan/skill 均开启。
- 先运行当前 harness 基线 9 轮，再运行视频经验条件 9 轮，各任务独立会话。
- 两条件共用同一冻结源码、场景、工具、上下文管理与评分器。区别仅为额外
  注入冻结的视频经验。每轮最多 80 次决策、120 次工具处理，无累计 token 截断。
  原版本 1800 秒后不再发起新调用；2026-10-15 经用户授权，新启动回合
  改为 `max_seconds: null`，不设单任务累计时长限制。旧结果与已加载旧时限的
  在途回合保留原配置，不能冒充已热更新。
- agy provider 会话最多复用两次决策，完整公开历史由原 session cache 保留。
  记录 provider 实际调用、图片读取和 usage，不把 harness 轮数冒充模型调用总数。

## 视频学习

从此前审核集固定选择与测试 task ID、源视频哈希都不重叠的三个 complex
视频（L1 积木、L2 蔬菜、L3 整理），不按执行成绩选择。每段视频真实解码，
概览均匀选择最多 12 帧，补充包选择 12 个帧序区间中点。真实时间戳与图片
哈希一起保存，不把帧序均匀误称为严格时间均匀。

每段视频使用两个全新模型会话：概览提出临时经验，补充证据修订。模型只能
读取哈希允许的图片并返回结构化结果；没有 shell、联网、答案文件、其他
会话、仿真或真机操作权限。每段最多三条，保留适用条件、建议、验证方式、
不确定性和具体帧引用；允许没有足够证据时返回零条。

经验库记录视频来源、用量、零学习阶段环境动作及冻结哈希。测试期间不更新
经验库，不把基线失败日志交给学习模型。所有正式目标仍来自各自示范，经验
不能替代最新反馈或升级为动作许可。

## 证据边界

- 帧引用合法且真实读取，不等于语义判断正确。修订来自同一模型，不能称为
  独立 oracle 或已验证物理技能。
- 学习集与测试集本次互斥，但九个任务已用于先前开发，并非全新盲测集。
- 四个任务的旧参考物理 rollout 未完整成功。保留九个任务和失败，另报这项
  环境混杂；启动时的连接/渲染检查不证明完整任务可达。
- 固定先基线后经验，存在供应商时间变化混杂；一次配对不能声称显著性。
- 本轮检验整个“视频经验包”的收益，不能单独区分更多输入 token、普通摘要、
  语言反馈修订和经验组织方式。后续需要独立消融。

## 使用

```sh
python tools/run_argon_video_study.py prepare --job /absolute/new-job \
  --reference /absolute/frozen-physics-job --video-pool /absolute/reviewed-video-job
python /absolute/new-job/source/tools/run_argon_video_study.py supervise --job /absolute/new-job
```

`state.json` 表示排程状态，`results.json` 保存逐轮报告；每轮的 `execution`
保存反馈和独立评分，`decision` 保存模型调用、图片审计和 usage；`learning`
保存视频学习过程。运行完成不等于任务成功。

已评分失败保留，不自动重试；基础设施、用量、评分或清理异常暂停。半途失败
的目录不覆盖，续跑需要先检查异常；无自动监视、发布或真机操作。

2026-10-14 续跑补充：经用户授权，agy 明确在推理准入阶段返回 503/429、
空会话、零轮次且完整 usage 明确为零时，最多追加三次请求，间隔 5/15/45 秒。
失败回执和流另存 admission-retries；未知传输结果、部分生成、缺 usage、
认证失败和动作错误不重试。视频学习使用同一机制。已中断回合仅在明确续跑
时新建场景和会话重跑，原成本与结果保留；已正常评分失败的回合不重跑。

2026-10-15：生成阶段收到明确连接重置/流中断的错误结果时，保存完整结果
（含部分文本与工具候选）、流日志和可确认的会话用量差分。错误候选不下发，
错误 plan 不写回；关闭 provider 会话，由 runner 重查公开持物状态、取得新
画面后，在下一轮独立会话重新决策。每任务最多追加三次，计入原调用/时间
预算，超过上限仍计失败成本并暂停。缺失用量或没有可解析结果的中断保存
原始流后暂停，不填零或猜测。视频学习最多追加三次，重读冻结帧，汇总失败
与成功的已知用量。已结束回合不重跑。

2026-10-15 第四次续跑：生成阶段 `UNAVAILABLE (code 503)` 与
`RESOURCE_EXHAUSTED (code 429)` 也进入同一有限恢复流程，仍须有可核验
usage 和会话身份。补上独立评分中的抽屉步骤：从成功运动的前后滑轨快照
检查位移变化，沿用原评分器开启 >=0.14 m、关闭 <=0.01 m；初态已经开启、
仅有末态或未执行动作不能代替执行证据。终态与顺序另验。此修正不反馈 GT
给模型、不修改控制器。前三个已结束任务以新评分重新核对结论相同，保留
原记录，未重新调用模型。历史第4题只拉开约9cm仍不满足既有开启阈值。


2026-10-15 单任务时长变更：`budget_revision=unbounded-task-time-v2`，只取消
累计任务时限，保留模型、物理、提示、80 次决策、120 次工具及既有错误暂停/
有界恢复规则。新报告和 `attempt.json` 明确保存 `execution_limits`、预算版本。
修改冻结作业须先核验旧哈希，归档旧配置/源码/冻结清单，记录生效回合和仍在
使用旧内存配置的回合，再更新冻结清单；不得覆盖已评分回合或自动重跑时限
失败。比较结果时同时核对物理与预算版本，跨版本差异不归因于视频经验。
