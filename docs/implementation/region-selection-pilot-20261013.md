# 选区表达与几何污染 pilot（2026-10-13）

## 要检验的问题

旧相机实验的抓取/放置辅助计算只接收矩形选区。框内高于桌面的深度点全部进入同一包络，后端并不识别哪个点属于目标。旧审计曾在两帧中精确复算出邻物污染；不能据此认定它是单双相机结果不同的唯一原因。

本轮拆成三个可检验问题：

1. 是否存在接口断层？已有 `scene_query` 支持 polygon，高层 `grasp_target/placement_target` 却不能传递。源码审查确认。
2. 合并框内两物体是否会改变几何结果？通过真实 CPU 几何 worker 的合成深度回归复现，不靠模型描述或测试替身计算结论。
3. 模型是否需要新分割器才能选对？从旧 single/dual 实验各取一张俯视录制图，让全新 Gemini CLI session 分别用矩形、多边形选择同一红圆柱。总计四个单决策回合，使用真实看图回执；不传旧框、GT、深度或评分。注意这是两张历史图片的选区小测，**不是新单双相机任务对照**，各回合仅看一张图。

## 最小代码改动

- 两辅助工具的 object/reference/table 各接受 `*_roi` 与 `*_polygon` 二选一。多边形直接复用既有 worker，不增加检测器、聚类器、求解器或动作工具。
- `oneOf` 在实际 Draft7 校验器下工作；保留矩形兼容，拒绝缺失、同时给两种表示和非法顶点。
- 向两次原生几何调用透传真实选区；候选图画相同轮廓，回执保留 worker 返回的 target region、点数量质量及平面内点支持。
- `selection_evidence.single_object_verified=false`：计算成功不表示模型选区属于单一物体，不把颜色诊断引入运行时。
- compact measurement 保留 selection_evidence，后续模型能够复核历史候选的依据。历史图和历史测量的时效规则不变。

仍未解决自动识别相邻物体、支撑面被遮挡、碰撞规划、持物滑移和任务完成语义。模型可以用 polygon 继续选错，因此不能把新增字段等同于定位正确。

## 验证与协作

113 项本地测试通过，覆盖 schema、两辅助工具到 worker 的矩形/多边形传递、图示与原图保持、真实 worker 双表面反例，以及既有上下文/动作反馈回归。透传测试使用执行器替身；双表面测试运行真实几何 worker。均不冒充物理任务成功。

通过终端调用 dsh 做方案审查和代码复核，没有创建 sub-agent。实验和审计产物位于 `/Users/nothing/DEV/piper-region-pilot-20261013/`；源码哈希与局部快照、真实 CLI 回执、调用记录、颜色审计脚本分别保留。旧冻结作业未修改。

颜色阈值只评估同一保存 JPEG 内显著红色/绿色像素的选择情况，不是人工分割真值，也不是三维精度。旧审计的深度有效点数字与这里的 RGB 像素数字口径不同，不应混用。新选区的旧深度复算遇到 Windows/WSL SSH 超时；在恢复前不声称毫米误差改善。

## 对标的含义

本轮核对本地保存的 GPT-Policy 源码快照 `3a74ed4b45d25ff9af4939c9209292e725712f50`：其 `vision/perception.py` 会将射线三角定位候选与通过视差、条件数、残差检查的米制定位区分；`harness/protocol.py` 区分 planned path 与 measured feedback，要求从新观察诊断失败。它已有计算与反馈，不应把我们的 RGB-D 工具存在本身当作超越。

这里可对标的原则是：几何工具说明自己实际算了哪些证据、数值成功与任务成功分开、证据不足时支持再次观察。下一步应优先验证候选选区的复核是否改变实际放置结果，而非继续增加工具数量。

四个模型回合的最终结果、用量和具体局限以外部 `report.zh.md` / `selection-audit.json` 为准；没有完成任务成功率比较、硬件部署、提交或发布。
